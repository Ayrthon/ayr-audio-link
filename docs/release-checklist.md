# AYR Audio Link — release checklist

Link ships with its own in-app updater (`src/updater.rs`) that polls
`https://api.github.com/repos/Ayrthon/ayr-audio-link/releases/latest`
on every startup. Releases cut on that repo's GitHub Releases page are
picked up automatically — no separate distribution / source split, unlike
the Meter. Link is a single public repo.

## One-time prerequisites

- Windows toolchain (rustup + MSVC build tools).
- Inno Setup 6 installed (`installer\build-installer.ps1` expects
  `ISCC.exe` under `%LOCALAPPDATA%\Programs\Inno Setup 6\` or Program Files).
- `gh` CLI authenticated against an account with write access to
  `Ayrthon/ayr-audio-link`.

## Every release

1. **Bump the version** in both places:
   - `Cargo.toml` → `version = "0.1.0"`
   - `installer/ayr-audio-link.iss` → `#define MyAppVersion "0.1.0"`

2. **Commit + push** the bump on the default branch:

   ```powershell
   git commit -am "release: 0.1.0"
   git push
   ```

3. **Build the installer** from repo root (~1 minute for the release
   build + ~5 s for ISCC). Output lands at
   `dist\AYR-Audio-Link-Setup-0.1.0.exe`:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\installer\build-installer.ps1
   ```

4. **Publish the GitHub Release**. The tag **must** start with `v` so
   the updater's `is_newer` comparator strips it cleanly.

   Release notes template (this block about the auto-generated `Source
   code` links should appear on every release so first-time users don't
   download the wrong file — GitHub won't let us hide those zips):

   ```md
   ### Install

   Download **`AYR-Audio-Link-Setup-0.1.0.exe`** from the Assets below and run it. Approve the firewall prompt during install.

   > ℹ️ The `Source code (zip)` and `Source code (tar.gz)` links are auto-generated by GitHub and are not the app. (GitHub does not let us hide them.)

   ### What changed

   Short changelog here. Bullets / links render fine in the updater banner.
   ```

   Then publish:

   ```powershell
   gh release create v0.1.0 `
     .\dist\AYR-Audio-Link-Setup-0.1.0.exe `
     --target main `
     --title "0.1.0" `
     --notes-file .\release-notes.md
   ```

5. **Smoke-test on two PCs:**
   - Install Link on PC A. Start broadcasting with any input device.
   - On PC B, open the Meter 2.x. Open the device dropdown. Within a few
     seconds the `[NET]` entry should appear.
   - Pick the `[NET]` entry, press Start. Speak / play audio on PC A.
     Levels should move on PC B within ~100 ms.
   - Close Link on PC A. The `[NET]` entry on PC B should disappear from
     the dropdown within ~30 s (mDNS TTL).
   - Reinstall an older Link build on PC A, then run the new installer.
     The updater banner should show "Update available" within seconds of
     launch.

## Troubleshooting

- **Meter doesn't see the sender.** Check the firewall rule was actually
  added (`netsh advfirewall firewall show rule name="AYR Audio Link"`). If
  the rule is missing — which happens when the user unticked the firewall
  task during install — re-run the installer or add the rule manually.
- **Updater banner never appears.** The Link updater logs through
  `env_logger`'s default sink; set `RUST_LOG=info` and relaunch from a
  terminal to see the `updater: checking ...` / `updater: up to date`
  lines. A 404 in that log almost always means the release is still a
  draft — the `releases/latest` endpoint only returns published releases.
- **Updater picks the wrong asset.** It grabs the first asset whose
  filename ends in `.exe` (case-insensitive). Never attach debug symbols
  or a second `.exe` alongside the installer.
- **mDNS dead on the LAN.** Some mesh routers cache mDNS records too
  aggressively; power-cycle the router. Corporate networks may block UDP
  5353 entirely, in which case Link doesn't work there — document it,
  don't try to tunnel around it.
